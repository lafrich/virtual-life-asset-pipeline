# Virtual Office · UI kit, emotes, mood icons, gallery frames
Owner: Raka (UI) · generated by `src/generate.py` · style per `art-direction/style-sheet.md` (Bima, v1).

Native 1x pixel art, transparent PNG, no anti-aliasing, 1px dark outline, top-left light with 3 values. Every native file `name.png` has nearest-neighbour upscales `name@2x.png` and `name@4x.png` next to it. Contact sheet: `preview_sheet.png` (4x on `wall_top` #5A6577).

## Re-render
```
cd assets/ui/src && python3 generate.py
```
Needs Python 3 + Pillow. Swap colours in `src/palette.json` (`colors`, `tints`, `alpha`) and re-run; the script wipes and rewrites the asset folders, the sheet and this README. Font glyphs live in `src/font.py`.

### Derived tints (signed off by Bima, review.md 21 Oct 2026; new keys still need a quick AD check)
The room accents and status colours have one value each, so buttons, dots and mood discs use straight RGB mixes of an AD colour toward `paper` (lighten) or `void` (darken): `light` = 35% toward paper, `hover` = 16% toward paper, `pressed` = 22% toward void, `dark` = 42% toward void, `shade` = 30% toward void, `hilite` = 40% toward paper. Signed off by Bima (review.md, 21 Oct 2026) with two rules: (1) warm hues (`glow`, `sharing`, `wait_user`, `brass`, `brass_lt`, `brass_shd`) lighten toward `glow` instead of paper; (2) `hilite` is capped at 40% toward paper. Where rule 1 makes `glow:hilite` equal to `glow` itself, discs use a single 1px `paper` specular instead.

## 9-slice insets
Insets are L,T,R,B in native px. Each source also ships as 9 pieces `<name>_{tl,t,tr,l,c,r,bl,b,br}.png`. Edges and centre are flat colour, so stretch or tile both work. In CSS: `border-image: url(<name>@2x.png) <inset*2> fill / <inset*2>px stretch; image-rendering: pixelated;`.

**Bubble tails.** `*_tail_*.png` are bottom-edge inserts, not overlays: their top rows (3 rows for bubbles, 2 for the name tag) reproduce the bottom edge with a gap. Build the bottom edge as `[bl][b stretched][tail][b stretched][br]`, so the tail sits flush and the translucent fill never doubles. See `samples/`.

## Gallery frame inner rects
The inner area is fully transparent (alpha 0); put the artwork underneath, or composite it with the matching mask in `frames/masks/`. Wall variants are the front frame sheared on the 2:1 grid: `back` = wall descending to the right (the build's back wall, `y += x//2`), `side` = wall rising to the right (the build's side wall at c=22.7, `y += (W-1-x)//2`). To place art on a wall frame, scale it to the front inner rect, then apply the same column shear.

## Frame usage and depth
- `ornate_gold` is for the Gallery's featured pieces only; everywhere else use `simple_wood` or `modern_black`.
- Depth per AD review: wall frames get a return edge (md 2px, sm 1px) in the frame's darkest value (`brass_shd`, `walnut_dk`, `void`) on the bottom + right (back wall) or bottom + left (side wall), outlined in void, plus a 1px `void` @ 40% (alpha 102) cast shadow below and right. Front frames get a 1px bottom + right return and the same shadow. Canvases and inner rects below include these.

## Emote notes
- `emotes/handshake.png` ships as the AD fallback (working green disc + paper check). The cuffed-hands version is kept as `handshake_hands_alt.png`; at 1x it read as a bar, not hands.

## Animation frames
- `status/dot_working_anim_f0..f7` spinner, ~100 ms/frame · `status/dot_thinking_anim_f0..f2` ~300 ms
- `emotes/typing_anim_f0..f2` ~250 ms · `emotes/thinking_anim_f0..f2` ~350 ms · `emotes/sparkle_anim_f0..f1` ~250 ms

## Colour semantics
Status dots follow the AD UI semantics: online = working green, busy = error red (bar), away = waiting-for-user amber (clock), offline = idle grey (hollow ring), working = green with spinner, thinking = waiting-for-bot blue with dots. Buttons: RUN = workspace green, Gallery = lounge plum, Talk / close = library oxblood, camera and D-pad = wall greys.
