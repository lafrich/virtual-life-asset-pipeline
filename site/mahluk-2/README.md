# Mahluk Hidup 2.0 — 2.5D Plane Studio

Standalone replacement candidate (not the existing production editor).
Open: https://lafrich.github.io/virtual-life-asset-pipeline/mahluk-2/

## Design

- Original V6B 64×112 RGBA art is read **non-destructively** from `../media/original-rig/manifest.json` (the same source pipeline as the existing Mahluk Hidup rig). No automatic low-poly character.
- Each body, hair and face cutout is a child of its own bone/node.
- Selected plane: X/Y position, Z depth and occlusion, angle, scale, visible.
- Body/head parenting is inherited. Facial planes (eyes, brows, mouth, blush, glasses) can choose a separate expression image while still following the head.
- Scene viewport is a **2.5D projected isometric editor**, not a volumetric 3D mesh. The right-hand 64×112 panel shows the actual composited game pixels.
- Move (W), rotate (E), scale (R) gizmos, axis X/Y/Z (1/2/3), keyframe (K), delete key, middle-drag pan, wheel zoom.
- The authored clip is exported as 64 × N pixel columns and 4 × 112 pixel rows (SE, SW, NE, NW) using the source cutouts. Movement/animation in game uses the same images and per-frame durations.

## Shared-origin game bridge

- Clicking `SAVE + SYNC CHARACTER` stores a JSON record in `localStorage["mahluk-2-library-v1"]`.
- Published actor ID: `mh2_...`. The record contains `format:"mahluk-2-character-v1"`, rig tree and transforms, `clips` (each a PNG data URL, number of frames and frame times), plus a composed preview sprite.
- `virtual-office/world-builder/mahluk-hidup-bridge.js` adds these published actors to the Semesta and Bangun Ruang catalogs. `pipeline-character-rig.js` composes the actual 3D-world billboard from the same four-direction frame strip. Only actions with an authored clip are advertised; missing actions remain unimplemented.
- Semesta character palette includes the `character:mh2_...` entry. Bangun Ruang `Mahluk Hidup / Scale Test` can preview the identical actor.
- Same **origin + browser profile** is required for this v1. Storage is local only; it does not upload custom characters to GitHub, and does not share between devices. Export Project JSON for a backup.
- Legacy character data, prior Mahluk Hidup, and city drafts are not deleted.

## Limitations

This version is an editable 2.5D *cutout* rig, not IK, dynamic skin weighting or a 3D mesh. It bakes the composed four-direction sprite clips; it does not preserve live C4D plane gizmos in Semesta. Game mechanics and non-authored actions still belong to Jiwa / dedicated animation data. Publish idle and, optionally, walk or other clips before using those actions in the game.

## Independent Emotion Plane + Glasses Plane (v2)

Character **Head**, **Emotion**, and **Glasses** are distinct, visually composited transparent planes.

- Emotion swaps **an image/animation asset**, rather than manipulating individual eye/brow/mouth/blush rig bones. The native V6B reference exposes its original seven facial assets, dynamically flattened into one Emotion Plane. They retain the exact original source paint.
- When the Human Male or Female base is chosen, the expression library additionally loads **the 12 existing authored expressions for that matching base**, including BLEH, CHEEKY, and GRIMACE BLUSH. Source: `assets/animation_library/expression_contexts.json` and the source Human expression atlases generated by `tools/build_human_templates.py`. `tools/build_mahluk2_emotion_planes.py` extracts their head-only RGBA pixels, preserving existing facial frames and timing, without copying full-body art onto the Emotion Plane. The library is published as `emotion-plane-library.json`; 24 source-specific 4-way atlases appear under `media/mahluk2-emotions/`.
- Users can import their own four-direction transparent PNG sprite atlas (`64 × frame_count` wide and exactly 448 high, 4 views), for animated emotions or an independent glasses/accessory plane. PNGs are saved in local app storage; they can also be bundled into Project JSON exports.
- Emotion image-swap keys are **not rig bone keys**; they have a separate row in the dope sheet. By contrast, spatial transforms of the entire Emotion Plane can still follow the head.
- Glasses is anchored to the **head**, not the Emotion Plane, so a facial emotion swap or a moved facial plane does not move the glasses. Phone is another independent transparent accessory plane.
- Published 4-direction animation clips are still baked into Semesta/Bangun Ruang's existing pixel billboard format, so both games stay compatible. This does not replace legacy NPC data or workflows.

Only use a published Human emotion asset on its corresponding Male/Female base. Using another actor's complete full-body expression animation directly would overwrite the character, so the build extracts face-only texture variants rather than treating those sheets as generic overlays.

## Master rig engine — universal default hierarchy, anchors, front/back and Undo (2026-11-05)

Mahluk Hidup 2.0 now owns a **reusable master rig rule document** in
`localStorage["mahluk-2-general-rig-rules-v1"]`. This is intentionally
separate from the immutable V6B artwork and per-character action tracks.
The master document stores:

- An **absolute pixel pivot** (anchor X/Y) per bone/plane, used for rotating
  and positioning each RGBA cutout. Editing an anchor at a neutral pose does
  not displace the original painting.
- **Editable parent hierarchy**, including `Head → Emotion` and
  `Head → Glasses`. Drag one object onto another in Object Manager or use
  the **PARENT** dropdown. Invalid self-parenting/cycles are refused.
- An optional **explicit draw-order stack**. Drag entries in the front/back
  list or use the ↑/↓ buttons to control which plane appears on top.
  Order is separate from spatial Z, so depth can be adjusted without
  silently changing the painter's stack.
- Optional **default part transforms** (rest pose). Clicking **SAVE AS
  GENERAL DEFAULT RIG** makes these rules available to new and reopened
  characters, Male/Female and custom originals. Per-character animation
  keyframes are not deleted.

Saved character records and project exports include the effective
`rigRules` and master revision used to author the baked 4-view sprite.
Opening an old record uses the latest shared master if present; project
imports may carry their own rig rules until the user applies the master.

**Versioning / safety:** Factory Reset only resets rules in the open editor
until explicitly saved. Existing old editor data and previous sprites are
never automatically rewritten. Previously published 4-direction sprites in
Semesta/Bangun Ruang still need a **re-publish** to reflect a master change.
Default storage is local to the current `lafrich.github.io` origin/browser;
export Project JSON when moving to another device.

**Undo/Redo:** toolbar or `Ctrl+Z` / `Ctrl+Shift+Z` (`Ctrl+Y`) for
plane edits, anchor moves, parent edits, front/back hierarchy, expression
swaps and animation key changes. A complete gizmo drag makes one undo step.

**Navigation:** scroll wheel to zoom with the mouse, **two-finger pinch**
(and pan by moving both fingers) on mobile, or use the `−` / `+`
zoom buttons. **One-finger drag** pans when the gizmo is not grabbed.
The cursor or pinch midpoint stays under the same point during zoom.
`W` Move, `E` Rotate, `R` Scale, `A` Anchor Pivot;
middle mouse drag pans. `⌖` resets zoom and viewport center.

## Body Plane Nude Swap (native male/female)

The **BODY PLANE TEXTURE** selector applies to the *currently open character* without switching its character base, rest pose, hierarchy, pivot, animation, expression, hairstyle, eyewear or other assets.

- `CURRENT / KEEP BODY`: original body appearance and existing Outfit setting, untouched.
- `NUDE / HUMAN MALE`: only body-bone cutouts are sourced from the existing original Human Male nude anatomy.
- `NUDE / HUMAN FEMALE`: only body-bone cutouts are sourced from the existing original Human Female nude anatomy.

Covered cutouts: torso, pelvis, shoulders, elbows, wrists/hands, hips, knees, ankles/feet. Head/neck, Emotion Plane, hair, Glasses Plane, phone and all other sources are excluded from replacement. Garment overlays on those body cutouts are hidden while nude is selected, **but the previous Outfit setting remains saved** and is restored automatically on CURRENT.

The PNGs already exist in the original rig manifest as `male/female` `layer_type:"body"` 4-view atlases. This mode only selects the cutout source. It does not regenerate anatomy, mutate body transform keyframes, change rig anchor rules or alter any other plane. It is reversible with Undo/Redo and persists in game saves and exported project JSON. Game previews and published Semesta/Bangun Ruang sprites use the same selection.

The selected base's head still stays intact when a body from the other base is selected; neck seams can vary between source anatomies, so inspect the 4-view preview before publishing. Older characters default to CURRENT on first opening.
